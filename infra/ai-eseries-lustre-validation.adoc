This section provides sizing guidance for building blocks, recommendations for scaling decisions, and the validation methodology used to characterize Lustre with NetApp E-Series Storage performance.

== Base building block capacity

A base building block with two EF80 arrays and TLC NVMe drives provides the following Lustre target layout:

.Base building block summary
|===
| Component | Count | Typical usable capacity (per target)

| MGS
| 1
| 5–10 GiB

| MDT
| 8
| Approximately 1–2 TiB each

| OST
| 32
| Approximately 22 TiB each (TLC, RAID6 layout)
|===

Usable capacity depends on drive capacity, RAID level, and volume allocation percentages in the Ansible inventory. Use the volume sizing percentages in the deployment template as a starting point and adjust for overprovisioning requirements.

For array-level performance specifications, see the link:https://www.netapp.com/pdf.html?item=/media/14036-ds-4082.pdf[NetApp EF-Series all-flash array datasheet^]. EF80 supports up to 5,000,000 IOPS and 57 GB/s write bandwidth per array under peak conditions.

== Scaling decisions

=== Add an OST-only building block when:

* File count and metadata load are within capacity of existing MDTs
* Additional storage capacity and aggregate read/write throughput are required
* `mdt.*.md_stats` on existing MDTs show no metadata saturation

An OST-only building block adds 32 OSTs and two server nodes without adding MGS or MDT capacity.

=== Add an MDT+OST building block when:

* File count or metadata operation rate is approaching MDT capacity
* `mdt.*.md_stats` on existing MDTs show elevated operation rates or latency
* Both additional metadata throughput and data capacity are required

An MDT+OST building block adds 8 MDTs and 32 OSTs.

=== Pacemaker cluster limits

Limit each Pacemaker/Corosync cluster to five building blocks (ten server nodes). For larger deployments, split building blocks evenly across multiple HA clusters. See link:ai-eseries-lustre-architecture.html[Solution architecture] for scaling rules.

== Validation methodology

Formal validation testing uses industry-standard HPC I/O benchmarks to characterize throughput, IOPS, and metadata performance:

* *IOR* - sequential and random read/write throughput at scale
* *mdtest* - metadata operation rates (create, stat, remove)
* *fio* - single-node and multi-node block-level characterization

Tests run from Lustre clients connected to the frontend fabric, with enough clients to saturate OST aggregate bandwidth. Tests include HA failover validation to confirm target recovery within acceptable service interruption windows.

== Sizing worksheet

Use the following checklist when sizing a deployment:

. Determine total usable capacity required today and at full scale-out.
. Estimate file count and metadata operation rate to determine MDT count.
. Calculate the number of base and additional building blocks required.
. Confirm that the total building block count per HA cluster does not exceed five.
. Confirm that server, HCA, and array models appear in IMT for *E-Series Lustre*.
. Select TLC (RAID6) or QLC (DDP) layout based on drive type.
